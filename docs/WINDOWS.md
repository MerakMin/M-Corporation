# 윈도우·네이버 웨일에서 시작하기

웨일은 계속 사용하셔도 됩니다. 이 프로그램의 **관리 화면은 웨일에서 열고**, 쇼핑몰 로그인은 프로그램이 여는 **별도 Chromium 브라우저**에서 합니다. 기존 웨일의 로그인 정보는 복사하지 않습니다.

현재는 관리 기능과 연동 기반이 구현된 상태입니다. 로그인 후에도 사이트별 문의 화면 설정과 실제 수집 검증이 필요합니다. 로그인만으로 모든 사이트의 문의가 자동으로 연결되는 것은 아닙니다. 셀메이트 연동은 포함되어 있지 않습니다.

## 1. 처음 설치

1. [Node.js 공식 사이트](https://nodejs.org/)에서 **24 이상 버전의 Windows 설치 파일**을 받아 설치합니다. 기본 설치 옵션을 사용하세요.
2. 프로그램 ZIP을 내려받아 **모두 압축 풀기**를 선택합니다. 압축파일 안에서 바로 실행하지 마세요.
3. 압축을 푼 `M-Corporation` 폴더에서 **01-install.cmd**를 더블클릭합니다. 인터넷으로 필요한 파일을 설치하므로 잠시 기다립니다.
4. **Installation complete**라는 문구를 확인한 뒤 창을 닫습니다. 오류가 나오면 완료된 것이 아니므로 표시된 오류를 확인하세요. 윈도우 문자 인코딩에 따른 오류를 피하도록 실행 파일의 안내는 영어로 표시합니다. 프로그램 관리 화면은 한국어입니다.

## 2. 프로그램 열기

1. **02-start.cmd**를 더블클릭합니다.
2. 열린 창에 표시되는 주소를 **웨일 주소창에 입력**합니다.
3. 예시 문의 10건이 있는 관리 화면이 열립니다. 프로그램 사용 중에는 실행 창을 열어 둡니다.

예시 모드는 실제 고객에게 답변을 보내지 않습니다. 우선 화면이 열리는지 확인하세요.

## 3. 쇼핑몰 로그인 — 패션플러스부터

1. 프로그램 실행 창에서 **Ctrl+C**를 눌러 종료합니다. 배치 작업 종료 확인이 나오면 `Y`를 입력합니다. 웨일은 닫지 않아도 됩니다.
2. **03-login.cmd**를 더블클릭하고 **1**을 누릅니다.
3. 새로 열린 브라우저에서 패션플러스에 로그인합니다. 필요한 2단계 인증도 직접 완료합니다. 비밀번호는 이 브라우저에만 입력합니다.
4. 고객 문의 화면이 열린 것을 확인하고, **03-login.cmd의 검은 창으로 돌아와 Enter**를 누릅니다. 브라우저가 닫히면서 세션을 저장합니다.
5. **02-start.cmd**를 다시 실행합니다. 채널 연결 화면에서 패션플러스 문의 화면 설정을 마친 뒤 실제 수집을 확인해야 합니다. 설정 전에는 자동 수집이 꺼져 있습니다.

패션플러스 고객문의는 아래 전용 수집기 설정을 사용하세요. 다른 문의함은 문의 행·내용·고유 ID·답변 입력란을 찾는 설정이 추가로 필요합니다. 비밀번호·인증 코드·`.data` 폴더는 공유하지 마세요.

다른 사이트는 03-login.cmd에서 해당 번호를 선택합니다. 같은 사이트의 여러 문의함은 로그인 세션을 공유합니다. **네이버 비욘드(7번)와 쿼터(8번)는 각각 로그인하고 올바른 스토어를 선택**해야 합니다.

## 4. 패션플러스 고객문의 수집 연결

2026-10-23 제공된 목록·상세 구조를 기준으로 고객문의 전용 수집기를 추가했습니다. **선택자 JSON을 입력할 필요가 없습니다.** 재현 화면 테스트를 통과했으며 실제 수집은 로그인된 PC에서 확인합니다.

업데이트할 때는 다음 순서로 진행하세요.

1. 실행 중인 검은 창에서 **Ctrl+C**로 서버를 종료합니다. 로그인·진단 브라우저도 닫습니다.
2. 최신 ZIP을 **모두 압축 풀기**로 새 폴더에 풉니다.
3. 새 폴더 안에서 `02-start.cmd`와 `src`, `public` 등이 보이는 위치로 들어가 **Ctrl+A → Ctrl+C**를 누릅니다.
4. 기존에 사용하던 `02-start.cmd`가 있는 프로그램 폴더로 들어가 **Ctrl+V**를 누르고, **대상 폴더의 파일 덮어쓰기**를 선택합니다. 기존 **`.data` 폴더는 삭제하지 않습니다.** ZIP에는 이 폴더가 없으므로 로그인과 데이터는 유지됩니다.
5. 기존 폴더의 **02-start.cmd**를 실행하고 관리 화면을 새로고침합니다.

연결 설정:

1. **채널 연결 → 패션플러스 연결 설정**을 엽니다.
2. **CS알리미 → 이 문의함 수집**과 **고객문의 게시판 → 이 문의함 수집**을 모두 선택합니다. 각 문의함에 전용 수집기 안내가 표시되는지 확인합니다.
3. **고객문의 게시판 → 이 문의함 수집**을 체크합니다. ‘전용 수집기’ 안내와 브랜드명 **비욘드마이셀프**를 확인합니다.
4. 맨 위 **자동 수집 활성화**를 체크하고 **설정 저장**을 누릅니다.
5. **실제 운영 → 지금 수집**을 누릅니다. 가져온 문의번호·본문·상품명을 플랫폼 원문과 대조합니다.
6. 답변 초안의 빈칸을 채우고 **초안 복사 → 원문에서 답변**을 이용합니다. 원문에서 기존 답변 유무와 문의번호를 확인한 후 직접 등록합니다.

프로그램 내 답변 전송은 아직 지원하지 않습니다. 원문에서 답변을 등록한 후 프로그램의 **지금 수집**을 누르거나 다음 10분 주기 수집을 기다리면 기존 대기 문의의 상세 원문을 다시 확인합니다. 원문이 명시적으로 **답변완료**이면 **답변 완료** 탭으로 이동합니다. 완료 화면에는 확인 시각과 **저장된 초안**을 표시하며, 실제 게시된 답변 본문이나 등록 시각으로 표시하지 않습니다. 로그인 오류·상세 번호/고객명/브랜드 불일치·확인되지 않은 상태는 완료로 바꾸지 않습니다. 오류는 채널 연결과 활동 기록에서 확인하세요. 문의 조회 기간은 사이트가 처음 표시하는 범위를 따르며, 목록을 못 읽은 경우를 ‘0건 성공’으로 처리하지 않습니다. 패션플러스는 목록 번호와 상세 문의번호가 다를 수 있어 두 번호를 별도로 표시합니다. 실제 제목 클릭으로 열린 문의의 고객명(목록의 가림 문자 포함)과 브랜드를 대조하며, 중복 상세 번호나 저장된 번호 연결의 변경이 있으면 수집을 중단합니다. CS알리미는 운영 알림으로 별도 표시하며 아래 8번 안내를 따릅니다. 다른 채널은 별도 연결이 필요합니다.

## 5. 패션플러스 문의 구조 진단 (문제 확인용)

현재 고객문의 구조 보고서는 이미 확보했으므로 정상 수집된다면 다시 진단할 필요가 없습니다.


패션플러스에 **CS알리미**와 **고객문의 게시판**을 별도로 등록했습니다. 2026-10-23 확인한 고객문의 주소는 `/cs-center/qna?status=1`입니다. 화면에서 ‘문의내용’, ‘답변’ 입력란, ‘고객에게 답변완료’ 버튼을 확인했습니다. CS알리미에는 플랫폼이 보낸 운영 알림도 포함되므로 두 화면을 혼동하지 마세요.

로그인이 끝났다면 서버와 이전 로그인 브라우저를 종료하고 **04-inspect-fashionplus.cmd**를 실행합니다. 실행 후 **1번은 고객문의 게시판**, **2번은 CS알리미**를 선택하며, 저장된 패션플러스 전용 로그인 세션을 사용합니다. 새 버전으로 업데이트할 때는 실행을 종료한 뒤 최신 ZIP의 파일을 기존 프로그램 폴더에 덮어씁니다. `.data`는 삭제하지 마세요. 서버를 먼저 실행하지 않아도 새 문의 주소로 진단할 수 있습니다.

1. 열린 브라우저에서 **문의 목록**이 보이면 검은 창으로 돌아와 **Enter**를 누릅니다.
2. 브라우저에서 **문의 한 건**을 직접 열어 본문과 답변 입력란을 표시합니다. **답변 등록을 누르지 말고**, 검은 창으로 돌아와 **Enter**를 누릅니다. 열 문의가 없으면 `s`를 입력합니다.
3. 프로그램 폴더의 **diagnostics** 폴더에 생긴 `fashionplus-qna-structure-날짜.json` 파일을 채팅에 첨부합니다.

CS알리미 구조를 확인할 때는 `04-inspect-fashionplus.cmd → 2번`을 선택합니다. 명령행에서는 `node scripts/inspect-fashionplus.js --notifications`를 사용할 수 있습니다. 같은 로그인 프로필을 공유하지만 보고서에는 대상 수집함을 구분해서 기록합니다.

보고서에는 요소 종류·배치 순서·고정된 화면 항목명·속성의 존재 여부만 들어갑니다. 고객명, 문의/답변 본문, 입력값, 속성값, URL, 쿠키, 브라우저 저장소, 스크린샷 및 HTML 원문은 저장하지 않습니다. 도구는 답변 입력·클릭·게시를 하지 않으며 자동 수집 설정도 변경하지 않습니다. 목록과 상세 화면 이동은 사용자가 직접 합니다.

이 보고서는 연결 방법을 파악하기 위한 자료입니다. 화면에 따라 추가 구조 확인이나 별도 연동 코드가 필요할 수 있으며, 진단 완료가 실제 수집·전송 완료를 의미하지 않습니다.

문의 목록을 저장하기 전에 등록된 주소와 현재 페이지 경로를 비교합니다. 로그인 후 메인 화면으로 이동했으면 문의 주소를 한 번 다시 열고 확인을 요청합니다. 그래도 주소가 다르거나 로그인 입력란이 보이면 저장을 중단합니다. 보고서에는 실제 URL 대신 경로 확인 여부만 기록합니다. 문의가 없다는 것은 사용자가 화면에서 확인해야 하며, 빈 표만으로 수집 성공을 판정하지 않습니다.

## 6. 쿠팡 문의 화면 진단

패션플러스의 문의 수집·수동 답변 등록·완료 상태 반영은 사용자 PC에서 확인했습니다. 쿠팡 고객 문의는 아래 7번의 전용 수집기를 사용합니다. 고객센터 문의 또는 변경된 화면은 이 진단 도구로 확인합니다. 진단 파일 저장 자체가 수집 연결 완료를 뜻하지 않습니다.

1. 위 업데이트 절차로 최신 파일을 기존 프로그램 폴더에 덮어씁니다. **`.data` 폴더를 삭제하지 않습니다.**
2. 프로그램 서버와 기존 로그인 브라우저를 종료하고 **05-inspect-coupang.cmd**를 실행합니다.
3. 먼저 **1번(Coupang product inquiries, 고객 문의)**을 선택합니다. 고객센터 문의를 확인할 때는 **2번**을 선택합니다. 두 화면은 같은 쿠팡 로그인 프로필을 사용합니다.
4. 열린 전용 브라우저에서 쿠팡 Wing에 로그인합니다. 이 도구 안에서 직접 로그인할 수 있어 `03-login.cmd`를 별도로 실행할 필요가 없습니다.
5. 선택한 문의 **목록**이 보이면 검은 창에서 **Enter**를 누릅니다. 로그인 후 메인으로 이동하면 도구가 문의 주소를 다시 열고 확인을 요청합니다.
6. 문의 한 건을 직접 열어 본문과 답변 입력란을 표시하고 다시 **Enter**를 누릅니다. 열 문의가 없으면 **s**를 입력합니다. **답변 등록은 누르지 않습니다.** 새 문의 창은 하나만 열어 둡니다.
7. `diagnostics` 폴더의 **coupang-product-structure-날짜.json** 파일을 채팅에 첨부합니다. 2번으로 진단했다면 이름은 `coupang-center-structure-날짜.json`입니다.
8. 진단 종료 후 `02-start.cmd`로 프로그램을 다시 실행하면 패션플러스 사용을 이어갈 수 있습니다.

구조 보고서에는 요소 종류·배치 순서·고정 항목명·속성 존재 여부만 기록됩니다. 고객 본문, 입력값, 속성값, URL, 쿠키, 브라우저 저장소는 포함하지 않습니다. 도구는 자동으로 문의를 클릭하거나 답변을 입력·게시하지 않으며, DB와 자동 수집 설정을 변경하지 않습니다. 기존 탭을 상세 문의로 잘못 저장하지 않도록 현재 목록에서 새로 연 팝업 또는 같은 탭만 사용합니다. 다른 출처의 프레임은 읽지 않고 생략 여부만 표시합니다.

2026-11-04 자료로 고객 문의의 목록과 기존 답변 배치를 확인했습니다. 고객센터 문의 구조는 아직 확인하지 않았습니다. 로그인 후에도 진단이 실패하면 오류 문구와 현재 화면 제목을 알려 주세요.

## 7. 쿠팡 고객 문의 수집 연결

1. 프로그램 서버를 Ctrl+C로 종료하고 최신 ZIP 내용을 기존 프로그램 폴더에 덮어씁니다. **`.data`는 보존합니다.** 진단 브라우저도 종료합니다.
2. `02-start.cmd`를 실행하고 프로그램을 새로고침합니다.
3. **채널 연결 → 쿠팡 → 연결 설정**에서 **고객센터 문의: 이 문의함 수집**을 해제합니다.
4. **고객 문의: 이 문의함 수집**을 선택하고 **자동 수집 활성화**를 켠 뒤 저장합니다. 전용 수집기 안내가 보이면 선택자 JSON은 필요하지 않습니다.
5. **실제 운영 → 지금 수집 → 답변 완료**를 확인합니다. 원문에 이미 답변이 있는 문의는 새 대기 문의가 아니라 완료로 들어오며, 최신 실제 게시 답변과 등록 시각을 표시합니다. 기존에 편집한 초안은 별도로 보존합니다.
6. 미답변 문의는 초안을 검토한 뒤 **초안 복사 → 원문에서 답변**을 사용합니다. 원문 링크는 목록을 여므로 **접수번호가 같은 문의인지 직접 확인**하고 등록합니다. 조회 범위 안에 남아 있는 문의는 다음 수집에서 완료 여부를 확인합니다.

답변여부는 `전체`로 조회하며 날짜·상품 조건은 사이트 기본값을 유지합니다. **현재는 전체 조회 결과가 한 페이지에 표시되는 경우만 지원합니다.** 화면의 전체 건수와 읽은 건수가 다르면 일부만 저장하지 않고 오류를 표시합니다. 고객센터 문의·여러 페이지 이동·완료 문의의 재개/비노출 상태 동기화는 별도 작업이 필요합니다. 실제 쿠팡 자동 수집은 사용자 PC에서 확인해야 합니다.

로그인 오류가 나면 서버를 종료하고 `03-login.cmd → 2번`에서 쿠팡 로그인을 갱신한 후 다시 실행합니다. 진단 때 로그인한 기존 프로필을 그대로 사용하므로 정상 로그인 상태이면 다시 로그인할 필요는 없습니다.

## 8. 패션플러스 두 문의함 함께 사용하기

최신 파일을 기존 폴더에 덮어쓴 후 `02-start.cmd`를 실행하고 새로고침합니다. **채널 연결 → 패션플러스 → 연결 설정**에서 CS알리미와 고객문의 게시판의 **이 문의함 수집**을 모두 선택하고, 각 브랜드명을 확인한 뒤 **자동 수집 활성화 → 설정 저장 → 지금 수집**을 누릅니다. 기존 고객문의 설정과 저장된 문의는 유지하며, 새로 추가한 CS알리미는 직접 선택해야 활성화됩니다. 쿠팡 작업은 패션플러스의 두 문의함 수집을 확인한 뒤 이어갑니다.

- 고객문의는 기존처럼 초안을 검토하고 원문에서 직접 답변합니다.
- CS알리미는 **운영 알림**입니다. 고객 답변 초안 대신 주문번호·순번, 주문자, 상품명, 회신기한, 알림 내용, 원문 처리상태와 종료 여부를 표시합니다. **CS알리미 원문에서 처리**로 이동해 직접 확인합니다.
- CS알리미 항목이 있으면 탭 이름은 **답변·처리 대기 / 답변·처리 완료**로 표시됩니다. **모든 문의함** 필터에서 **CS알리미**와 **고객 문의**를 각각 볼 수 있습니다.
- 원문의 처리상태가 **답변완료 또는 처리완료**이고 **문의종료여부가 종료**일 때만 CS알리미를 처리 완료로 표시합니다. 조회 목록에서 사라졌다는 이유로 완료 처리하지 않습니다. 아직 대기 중인 저장된 알림은 상세 원문을 다시 확인합니다.
- 알림의 지시 문구를 프로그램이 실행하지 않습니다. 출고일 등록, 송장 등록, 취소, 답변 등록은 자동 처리하지 않습니다.
- 한 문의함 읽기에 실패해도 다른 문의함의 성공 결과는 저장합니다. 채널 카드에는 실패한 문의함 이름과 오류가 표시됩니다.

CS알리미는 이전에 제공된 화면과 저장된 구조 설명으로 구현해 재현 화면에서 검증했습니다. **사용자 PC의 실제 수집과 종료 상태 확인은 아직 필요합니다.** 문의가 없으면 명시적인 0건 여부를 확인합니다. 화면 구조 오류가 나면 `04-inspect-fashionplus.cmd → 2번`으로 현재 목록과 상세를 진단해 생성된 `fashionplus-notifications-structure-….json` 파일을 보내 주세요. 이때도 답변이나 주문 처리는 실행하지 않습니다.

## 자주 막히는 부분

- **한글이 깨지고 ‘내부 또는 외부 명령이 아닙니다’가 반복됨:** 초기 실행 파일의 인코딩·줄바꿈 문제입니다. 수정된 최신 ZIP을 새 폴더에 모두 압축 해제해 실행하세요. 기존 폴더에 로그인·문의 데이터가 있다면 `.data`를 삭제하지 마세요.
- **Node.js를 찾지 못함:** 설치 후 실행 파일을 다시 엽니다. 계속되면 PC를 재시작합니다.
- **브라우저 실행 파일이 없음:** 01-install.cmd가 끝까지 성공했는지 확인합니다.
- **주소/포트를 이미 사용 중이라는 오류:** 이미 열린 프로그램 실행 창이 있는지 확인합니다. 다른 프로그램을 임의로 종료하지 마세요.
- **브라우저 프로필이 사용 중이라는 오류:** 프로그램 서버와 이전 로그인 브라우저를 종료한 뒤 다시 실행합니다.
- **‘고객문의 전체 건수와 페이지 수를 확인하지 못했습니다’ 오류:** 최신 버전에는 페이지 수와 건수가 별도 요소로 표시되는 화면 및 건수 표시의 지연 로딩을 처리하는 수정이 포함되어 있습니다. 서버를 종료하고 최신 파일을 덮어쓴 뒤 다시 수집하세요. 이 오류는 문의 목록을 읽는 중 발생하므로 로그인 오류와 구분합니다.
- **로그인 후에도 문의가 없음:** 웨일 로그인만 했거나, 사이트별 문의 화면 설정을 아직 마치지 않았을 수 있습니다. ‘세션 저장’ 메시지는 수집 성공을 뜻하지 않습니다.

데이터와 로그인은 압축을 푼 폴더 안의 `.data`에 저장됩니다. 업데이트할 때 이 폴더를 지우지 마세요. 서버를 종료한 상태에서 폴더 전체를 백업할 수 있습니다.

이 배포본의 Node.js 기능은 Linux에서 테스트했습니다. 윈도우 `.cmd` 파일의 실제 실행은 아직 Windows PC에서 검증하지 않았습니다.
