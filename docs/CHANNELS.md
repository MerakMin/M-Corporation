# 채널 연결 안내

실제 채널 수집·전송에는 **문의 URL, 해당 PC의 로그인 세션, 화면 선택자 매핑**이 필요합니다. 플랫폼별 완성형 공식 API 커넥터나 검증된 선택자가 포함된 것은 아닙니다.

PDF의 ‘로그인만 해 두면 동작’은 별도의 브라우저 조작 에이전트를 전제로 합니다. 이 구현은 로컬 Playwright 브라우저를 사용하므로 평소 사용하는 Chrome 로그인과 세션이 분리됩니다. PC를 바꾸면 로그인도 다시 해야 합니다.

## 등록된 채널과 로그인 명령

사용자가 제공한 **17개 문의 주소를 9개 로그인 프로필**에 등록했습니다. 문의함별 원문 링크는 대시보드의 채널 연결 화면에 표시됩니다.

| 채널·계정 | 로그인 명령 | 문의함 |
| --- | --- | --- |
| 패션플러스 | `npm run login -- fashionplus` | CS알리미 1개; 고객문의 게시판은 별도 주소 확인 필요 |
| 쿠팡 | `npm run login -- coupang` | 고객센터 문의, 고객 문의 2개 |
| 카페24 자사몰 | `npm run login -- cafe24` | 미답변 상품 문의 1개 |
| 하이버 | `npm run login -- hiver` | 답변 대기 Q&A 1개 |
| 에이블리 | `npm run login -- ably` | 셀러 문의 1개 |
| 룩핀 | `npm run login -- lookpin` | 1:1 문의, 상품 Q&A 2개 |
| 네이버 비욘드 | `npm run login -- smartstore` | 상품 Q&A, 페이 Q&A, 고객센터, 톡톡 4개 |
| 네이버 쿼터 | `npm run login -- smartstore_quarter` | 상품 Q&A, 페이 Q&A, 고객센터, 톡톡 4개 |
| 네이버 페이센터 | `npm run login -- naverpay` | 고객 문의 1개 |

기존 네이버 톡톡·카카오 설정과 실제 문의가 있는 설치본에서는 해당 기존 채널도 보존합니다. 초기 예시 화면의 문의만 새 채널 구성에 맞게 옮기고, 사용자가 편집한 초안과 실제 문의는 보존합니다.

### 패션플러스 CS알리미와 고객문의 게시판

등록된 `/cs-center/cs-notification?status=1` 주소는 **CS알리미**입니다. 2026-10-22 사용자가 제공한 화면과 구조 보고서에서 패션플러스의 자동 배송 관리 알림임을 확인했습니다. 고객이 직접 남기는 문의 게시판과 구분해야 합니다. 초기 기본 이름 ‘고객 문의’는 해당 원래 주소에 한해 ‘CS알리미’로 정정하며, 사용자가 변경한 이름·주소·선택자는 보존합니다.

확인된 목록은 문의번호·처리상태·브랜드·주문번호·고객명·문의유형·문의일자·회신기한을 표시합니다. 헤더 표와 데이터 표가 분리되어 있고, 처리상태의 링크에서 상세 화면을 엽니다. 상세에는 ‘문의상태’, ‘문의종료여부’, ‘상품명’, ‘알림내용’ 등이 있으며, 확인한 완료 건에는 답변 입력란이나 등록 버튼이 없습니다. ‘답변완료’라는 상태만으로 판매자가 고객에게 보낸 답변 본문이 존재한다고 판단하지 않습니다. 미처리 건의 입력 화면은 아직 확인하지 않았습니다.

현재 자료는 CS알리미의 구조 확인 자료이며 실제 수집·전송 검증 결과가 아닙니다. 기존 자동 수집 설정은 활성화하지 않습니다. ‘고객문의 게시판’ 주소는 사용자가 실제로 여는 페이지를 확인한 뒤 별도 수집함으로 등록합니다. 알림 본문에 적힌 주문 상태·출고일·취소 처리 안내를 프로그램이 자동 실행하지 않습니다.

### 네이버 계정 구분

비욘드와 쿼터의 URL은 동일하지만 브라우저 프로필 경로가 각각 `.data/profiles/smartstore`, `.data/profiles/smartstore_quarter`로 다릅니다. 로그인할 때 해당 스토어를 각각 선택하세요. 같은 네이버 로그인으로 스토어를 전환하는 구조여도 두 프로필에서 각각 올바른 스토어를 선택해야 합니다.

채널 설정의 **로그인 스토어 확인**에 화면에서 현재 선택된 스토어명을 나타내는 요소의 CSS 선택자와 정확한 텍스트를 입력합니다. 기본 예상 이름은 ‘비욘드마이셀프’, ‘쿼터’이며 실제 화면에 표시되는 이름이 더 길다면 그 전체 이름으로 수정하세요. 목록 수집 전과 답변 입력 전에 해당 값이 일치하는지 확인합니다. 일치하지 않거나 선택자가 없으면 수집·전송하지 않습니다.

쿼터 채널의 답변 상호는 ‘쿼터’입니다. 다른 정확한 상호를 사용한다면 **답변에 사용할 상호**에서 수정하세요. 공통 답변 템플릿의 `{{shop}}`에 채널별 상호가 반영됩니다. 빈 상호는 공통 설정인 비욘드마이셀프를 사용합니다.

### 날짜가 있는 문의함

카페24의 `start_date/end_date/period`, 하이버의 `from/to`는 한국 시간의 오늘과 30일 전을 수집할 때마다 계산합니다. 원래 전달된 URL은 설정에 보관되고 실제 접속 주소만 갱신됩니다. 미답변 조건 등 다른 검색값은 유지됩니다. 대시보드의 문의함 링크도 현재 날짜로 열립니다.

연결 설정에서 조회 기간을 1~365일로 바꿀 수 있습니다. **조회 날짜 자동 갱신**을 끄면 직접 입력한 URL의 날짜를 사용합니다. 설정 변경 후 다시 시작해도 선택을 유지합니다.

## 연결 순서

1. **채널 연결 → 연결 설정**에서 미리 등록된 문의 관리 URL을 확인합니다. 처음에는 자동 수집을 끈 채 저장할 수 있습니다.
2. 서버를 종료하고, 화면이 있는 PC에서 `npm run login -- cafe24`처럼 실행합니다. 열린 브라우저에서 직접 로그인·2단계 인증을 마치고 문의 화면을 연 다음 터미널에서 Enter를 누릅니다.
3. `npm start`로 다시 실행합니다. 실제 DOM 구조에 맞게 선택자를 입력합니다. 브라우저 개발자 도구로 확인하거나 개발자에게 매핑을 요청합니다. 비밀번호나 세션 파일을 채팅에 붙여 넣지 마세요.
4. 설정이 끝난 문의함의 **이 문의함 수집**을 선택하고 **자동 수집 활성화**를 켜서 저장합니다. 아직 설정하지 않은 문의함은 수집 선택을 해제해 둘 수 있습니다. **실제 운영 → 지금 수집**으로 수집 결과와 원문을 대조합니다.
5. 문의 ID·본문·고객명이 확인되면 답변을 편집·검토하고 전송합니다. 게시된 답변 원문까지 확인되어야 완료 처리됩니다.

서버 실행 중 10분마다 활성 채널을 수집합니다. 수동 수집 완료 시 다음 주기는 10분 뒤입니다. 종료·절전 중에는 수집하지 않습니다. 로그인 만료·화면 변경은 해당 채널 오류로 표시되며 다른 채널은 계속 처리합니다.

로그인 명령은 채널 설정만 읽으며 문의·초안·전송 상태를 변경하지 않습니다. 첫 실행에서 DB가 없으면 등록된 기본 주소를 사용합니다. 브라우저를 닫아 세션을 저장했다는 메시지만으로 로그인이나 수집 성공이 확인되는 것은 아닙니다.

클라우드에 그래픽 브라우저 화면이 없다면 직접 로그인을 끝낼 수 없습니다. 개인 PC에서 프로그램을 실행하는 방법을 권장합니다. 로그인 세션을 자동 복제하거나 캡차를 우회하지 않습니다.

## 선택자 계약

아래는 **테스트용 화면 예시**이며 실제 쇼핑몰의 선택자가 아닙니다.

```json
{
  "ready": "main.inquiry-list",
  "row": "article.unanswered",
  "idAttribute": "data-id",
  "title": ".title",
  "customer": ".customer",
  "body": ".body",
  "product": ".product",
  "date": "time",
  "link": "a.detail",
  "next": "a.next",
  "empty": ".empty-state",
  "login": "form.login",
  "detailIdentity": "main.inquiry-detail",
  "detailIdAttribute": "data-id",
  "editor": "textarea[name=reply]",
  "submit": "button[type=submit]",
  "confirm": "",
  "postedReply": ".seller-reply"
}
```

| 필드 | 의미 |
| --- | --- |
| `ready` | 로그인 후 표시되는 문의 목록 컨테이너. 로그인 화면과 구별되어야 합니다. |
| `row` | 미답변 문의 한 건의 행. |
| `idAttribute` | 행의 안정적인 고유 ID 속성. 목록 순번·고객명은 사용하지 않습니다. |
| `title`, `customer`, `body`, `product`, `date` | 각 행 안에서 찾는 선택자. `body`는 필수입니다. `date`는 파싱 가능한 날짜에 사용하며 생략하면 수집 시각을 사용합니다. |
| `link` | 행 안의 고유 상세 페이지 링크. 같은 출처의 HTTPS 링크여야 합니다. |
| `next` | 다음 페이지 버튼. 선택 사항. 한도 도달·반복 페이지는 오류 처리합니다. |
| `empty` | 문의가 없다는 명시적 표시. 행이 0개이면 이 요소를 확인해야 정상 빈 목록으로 인정합니다. |
| `login` | 로그인 필요 상태를 탐지하는 요소. 선택 사항. |
| `detailIdentity`, `detailIdAttribute` | 상세 화면의 문의 요소와 ID 속성. 목록 ID와 다르면 전송하지 않습니다. |
| `editor` | 답변 입력 요소. textarea, input, contenteditable을 지원합니다. |
| `submit` | 실제 답변 게시 버튼. |
| `confirm` | 추가 확인 버튼이 필요한 경우 지정합니다. |
| `postedReply` | 해당 문의의 게시된 판매자 답변 본문. 입력란·전체 채팅방이 아닌 실제 결과와 정확한 내용을 비교합니다. |

`row`, `next`, `postedReply`는 표준 CSS 선택자를 사용하세요. 고유 링크 없이 열리는 상세 화면, iframe·Shadow DOM·가상 스크롤·파일 업로드가 필요한 플랫폼은 `src/connectors.js`에 별도 어댑터를 구현해야 할 수 있습니다.

대화형 채널에는 **각 메시지/문의 회차별 고유 ID**가 필요합니다. 중복 키는 `(모드, 채널, 수집함, 문의 ID)`입니다. 변경된 본문으로 기존 문의를 덮어쓰지 않으므로 메시지 단위로 매핑하세요.

## 불명확한 전송 결과

전송 버튼 클릭 이후 연결이 끊기거나 서버가 종료되면 ‘게시 확인 필요’가 됩니다. 자동 재전송하지 않습니다. 플랫폼 원문을 확인한 뒤 **게시된 답변 확인** 또는 **미게시 확인 · 대기로**를 선택하세요. 이미 동일 답변이 있으면 추가 게시 없이 완료 처리하며, 다른 답변이 있으면 중복 게시를 막습니다.

## 상품 실측 수집

**상품 실측 DB → 웹에서 수집**에서 공개 상품 상세 URL(최대 50개)과 선택자를 입력합니다. 상품명은 페이지 전체에서, 사이즈와 수치는 각 행 안에서 읽습니다.

```json
{
  "name": "h1.product-name",
  "row": "table.measurements tbody tr",
  "size": "td:nth-child(1)",
  "length": "td:nth-child(2)",
  "shoulder": "td:nth-child(3)",
  "chest": "td:nth-child(4)",
  "waist": "td:nth-child(5)"
}
```

위 선택자도 예시입니다. 이미지 실측표·범위·인치 단위는 추측하지 않고 오류로 남깁니다. 텍스트의 cm 수치만 읽으며 직접 입력과 JSON 가져오기도 지원합니다. 전체 카탈로그 탐색과 키·몸무게만으로 추천 사이즈를 추정하는 기능은 포함하지 않습니다. 정확한 상품명이 일치하는 실측과 개인차 안내를 초안에 반영합니다.


## 현재 클라우드 접속 상태

2026-10-22에 로그인하지 않은 새 Chromium 세션으로 확인한 결과입니다. 주소 등록과 로컬 테스트는 완료했으며, 실제 로그인 세션과 문의 화면 선택자 매핑은 아직 없습니다.

| 플랫폼 | 관찰한 결과 |
| --- | --- |
| 패션플러스·하이버·에이블리·룩핀·네이버 페이센터 | 로그인 화면 확인. 실제 인증·문의 수집은 미검증. 하이버·룩핀의 일부 백엔드 요청은 차단됨. |
| 쿠팡 | 재확인 시 별도 인증 서버 `xauth.coupang.com`의 로그인 화면과 비밀번호 입력란 확인. 실제 로그인은 미검증. |
| 네이버 스마트스토어 | 재확인 시 공개 `/home` 화면에 접근. 실제 계정·문의 화면은 미검증. |
| 카페24 | 제공된 문의 주소에서 HTTP 403. `/admin`은 HTTP 200 후 `eclogin.cafe24.com`으로 이동하다 프록시 연결 실패. 인증 후 문의 경로 유효성 확인 필요. |

Chromium의 인증서 저장소 초기화에 필요한 `/home/agent/.pki/nssdb` 쓰기 접근을 허용한 뒤 HTTPS 인증서 검증 오류가 해소되었습니다. 이미 설치된 플랫폼 CA를 사용했으며 인증서를 추가하거나 TLS 검증을 끄지 않았습니다. 이 권한은 현재 작업에 한정되므로 새 작업에서 오류가 재발하면 저장소 접근 권한을 먼저 확인해야 합니다.
